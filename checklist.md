## 🧠 PHASE 1 — Core Auto-Commit Engine (MVP)

> Goal: Have a minimal idle-trigger auto commit working end to end.

### Tasks

- [ ] Implement `CommitService` under `src/services/CommitService.ts`:

  - `addAll()`, `commit(message)`, `push()`.
  - Use `child_process.exec` for now (simplest path).

- [ ] Implement a basic **idle trigger** in `src/triggers/idle.ts`:

  - Watch file saves or editor activity.
  - Reset timer on activity, commit on inactivity.

- [ ] Wire this idle trigger inside `extension.ts`.
- [ ] Hardcode commit message (e.g., `chore(auto): save work in progress`).
- [ ] Manually test:

  - Save file
  - Wait X seconds
  - ✅ Auto commit happens

💡 **Why this first?**
Because this is the _core differentiator_ of your product. Even without AI, UI, or config — this proves the extension’s backbone.

👉 Milestone outcome:

## 🪝 PHASE 3 — Additional Triggers

> Goal: Make auto-commit intelligent (branch switch, save burst, etc.)

### Recommended order:

1. **Branch Switch Trigger**

   - Hook into `onDidChangeActiveTextEditor` + Git HEAD change.
   - Commit before switching branch.

2. **Save Burst Trigger**

   - Debounce multiple file saves, commit once after burst.

3. **(Optional)** Test Pass Trigger

   - Future integration — can stub it out for now.

💡 **Tip:** Reuse logic in `CommitService`. Don’t repeat commit code in every trigger.
